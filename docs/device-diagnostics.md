# Device Environment Diagnostics

## 1. The Core Hardware Reality

Google Pixel device promotions are **hardware-bound entitlements**, not web browser features. They are cryptographically governed by:

1. **Google Play Services (GMS) Checkin**: Matches hardware serials and IMEI against factory retail point-of-sale inventory records.
2. **Google Play Integrity API (formerly SafetyNet / DroidGuard)**:
   - Assesses `MEETS_BASIC_INTEGRITY`: Basic Android runtime with unmodified core libraries.
   - Assesses `MEETS_DEVICE_INTEGRITY`: Official Google-certified Android build running on verified OEM hardware with locked bootloader.
   - Assesses `MEETS_STRONG_INTEGRITY`: Hardware-backed keystore proof generated by the **Titan M2** security coprocessor.
3. **Verified Boot (`ro.boot.verifiedbootstate == green`)**: Custom ROMs or unlocked bootloaders immediately invalidate device entitlement tokens.

## 2. Classification Hierarchy

The diagnostic engine assigns one of five deterministic classifications:

```
                      [ Host Inspection ]
                               │
               ┌───────────────┴───────────────┐
      [ No Android Runtime ]          [ Android Runtime / ADB ]
               │                               │
       Browser / CDP Active           Virtual vs Physical
               │                               │
     BROWSER_SIMULATION          ┌─────────────┴─────────────┐
                           Goldfish/Ranchu              Bare-Metal OEM
                                 │                           │
                          ANDROID_EMULATOR            PHYSICAL_ANDROID
                                                             │
                                                      Google OEM + Titan M2
                                                      + Locked Bootloader
                                                             │
                                                      VERIFIED_PIXEL
```

### Classification Definitions

| Classification Code | Meaning | Hardware Proof Status | Promotional Claim Status |
|---|---|---|---|
| `BROWSER_SIMULATION` | Host is running a desktop web browser (Chrome/Chromium) with modified User-Agent or CDP viewport metrics. | Zero hardware attestation | **Ineligible**. Fails Play Integrity by definition. |
| `ANDROID_EMULATOR` | Host is running an Android Studio AVD or QEMU virtual instance. | Virtual software attestation only | **Ineligible**. Fails `MEETS_DEVICE_INTEGRITY`. |
| `PHYSICAL_ANDROID` | Bare-metal Android smartphone connected via ADB, but not verified as a compliant retail Pixel. | Hardware attestation present, but non-Pixel or modified | **Ineligible** for Pixel-exclusive bundles. |
| `VERIFIED_PIXEL` | Genuine Google Pixel phone with official Google firmware, locked bootloader, and verified Play Services. | Full Titan M2 hardware keystore attestation | **Eligible**. Ready for on-device app activation. |
| `UNKNOWN` | Environment signals are insufficient or ambiguous. | Unverified | Requires ADB physical connection. |

## 3. The Strict Model Rule

> **CRITICAL RULE**: Do not classify a device as `VERIFIED_PIXEL` based only on model strings.

A browser sending `Sec-CH-UA-Model: Pixel 11 Pro` or an Android emulator setting `ro.product.model=Pixel 11 Pro` does **not** make it a verified Pixel device. The diagnostic service requires:
- Physical hardware execution (`PHYSICAL_ANDROID`).
- Genuine manufacturer tags (`Google`).
- Locked bootloader state (`ro.boot.flash.locked == 1` or `ro.boot.verifiedbootstate == green`).
- Installed and certified Google Play Services (`com.google.android.gms`).
